## النتيجة التنفيذية

البناء واختبارات المشروع ناجحة، لكن توجد **6 ملاحظات على التنفيذ والإعدادات** تستحق المعالجة، بالإضافة إلى مشكلة في بيئة التطوير المحلية و5 تحسينات مقترحة. لم تثبت هذه المراجعة ثغرة حرجة أو عالية الخطورة قابلة للاستغلال في الكود الحالي. هذا استنتاج ضمن نطاق الاختبارات المذكورة، وليس شهادة أمان للبنية الإنتاجية.

أهم النتائج: فشل التوليد الثابت على Windows بسبب إعداد توازٍ غير فعّال، قصّ قائمة الموبايل في الشاشات القصيرة، وإمكانية عرض نجاح وهمي في نموذج التواصل عند ضبط وجهته بصورة خاطئة. النموذج غير موصول حاليًا بخدمة إرسال؛ تعطيله عند غياب الوجهة قرار مقصود، وليس عطلًا أدرجناه ضمن الأخطاء.

**الالتزام بالقيد:** لم تُعدَّل ملفات الواجهة أو المحتوى أو إعدادات المشروع أو ملف القفل. الملف الوحيد المضاف إلى المشروع هو هذا التقرير. البناء والتثبيت والتجارب التشخيصية تمت في مجلدات مؤقتة خارج المشروع، دون نشر أو commit أو push أو إرسال بريد حقيقي.

### F01 — P2: إعداد تقليل توازي prerender غير فعّال، والتوليد يفشل محليًا

**الملفات:** [deploy-pages.yml:46](C:/Projects/binzomh-web/.github/workflows/deploy-pages.yml:46)، [nuxt.config.ts:57](C:/Projects/binzomh-web/nuxt.config.ts:57).

**الكود المعني:**

```yaml
NITRO_PRERENDER_CONCURRENCY: 1
```

```ts
nitro: {
  prerender: { crawlLinks: false },
},
```

**المشكلة:** تعليق الـworkflow يفترض أن المتغير يفرض التنفيذ المتسلسل، لكن الإعداد الفعلي للإصدارات المستخدمة لا يقرأ هذا المتغير إلى `nitro.prerender.concurrency`. الإعداد الافتراضي في `@nuxt/nitro-server` هو عدد المعالجات المنطقية × 4.

**دليل إعادة الإنتاج:** في نسخة نظيفة على Windows، مع نفس متغيرات النشر و`NITRO_PRERENDER_CONCURRENCY=1`، قرأ hook التشخيص:

```json
{"env":"1","resolvedConcurrency":80}
```

فشل `npm run generate` مع `EPERM: operation not permitted, rename` لملفات payload في cache. حدث الفشل في نسختين مستقلتين. عند تمرير `nitro.prerender.concurrency: 1` مباشرةً إلى Nuxt في الذاكرة، نجح توليد 55 مسارًا.

**الأثر العملي:** مسار تجهيز النسخة الثابتة محليًا غير موثوق، والتعليق يوحي بحماية غير مطبقة. لا يوجد دليل هنا على فشل GitHub Actions على Linux؛ لم يُشغّل ذلك الـrunner ضمن المراجعة.

**الإصلاح المقترح:** ضبط `nitro.prerender.concurrency` فعليًا في إعداد التوليد، أو قراءة متغير بيئة مخصص وتحويله إلى هذا الخيار والتحقق من قيمته. تثبيت الإعداد الذي نجح تشخيصيًا، وتحديث التعليق. لا يحتاج ذلك لتغيير التصميم.

**اختبار القبول:** توليد من تثبيت نظيف على Windows بالإعداد الموثق، بلا `EPERM`، مع تحقق صفحات اللغتين والأصول تحت base path. تشغيل فحص Linux مستقل قبل اعتماد إصلاح النشر.

### F05 — P3: بيانات WebSite المنظمة تتجاهل مسار GitHub Pages

**الملف:** [app.vue:21](C:/Projects/binzomh-web/app/app.vue:21).

**الكود المعني:**


**المشكلة:** `useSiteUrl` يطبق الـorigin فقط، بينما هذه الاستدعاءات لا تضيف `app.baseURL` كما يفعل sitemap وrobots.

**الدليل من HTML المولّد:** canonical الصفحة هو `https://engmuhammednasser.github.io/binzomh/en`، لكن JSON-LD يحمل:

```json

  "@id": "https://engmuhammednasser.github.io/#website",
  "url": "https://engmuhammednasser.github.io/"
}
```

**الأثر العملي:** تعريف الموقع في structured data يشير إلى جذر حساب GitHub بدل موقع المشروع. لا تظهر المشكلة عندما يكون base path هو `/` على الدومين النهائي.

**الإصلاح المقترح:** تطبيق base path على عنوان الموقع و`@id` باستخدام helper موحد، وإضافة اختبار للـschema مع `/binzomh/`. الاختبارات الحالية تتحقق من النشر على الجذر فقط.

**اختبار القبول:** `url` يساوي `https://engmuhammednasser.github.io/binzomh/` و`@id` ينتهي بـ`/binzomh/#website`، مع بقاء حالة الجذر سليمة.

### I02 — P3: تقوية رؤوس أمان الاستضافة بعد التحقق من البيئة النهائية

**المرجع والكود:** [nuxt.config.ts](C:/Projects/binzomh-web/nuxt.config.ts) لا يضبط سياسة رؤوس أمان للصفحات، ولا يوجد middleware أمني في [server](C:/Projects/binzomh-web/server). رد SSR المحلي على `/en` احتوى `content-type` و`x-powered-by: Nuxt` دون CSP أو `X-Frame-Options` أو `X-Content-Type-Options` أو `Referrer-Policy` صريحة.

**المشكلة والأثر:** غياب دفاع إضافي ضد التضمين غير المرغوب وتقليل أثر أخطاء مستقبلية. **لم يُثبت استغلال clickjacking مؤثر أو XSS، ولم تُفحص رؤوس الدومين المنشور**؛ قد تضيف الاستضافة سياساتها بنفسها. لذلك هذه تقوية أمنية منخفضة الأولوية وليست ثغرة عالية.

**التحسين:** فحص رؤوس الإنتاج ثم تطبيق سياسة مناسبة في طبقة الاستضافة/الـproxy. تضمين `frame-ancestors` المناسب، و`nosniff` وسياسة referrer، وتجربة CSP في وضع Report-Only قبل فرضها لكي لا تتعطل سكربتات Nuxt أو الواجهة. بالنسبة للنسخة الثابتة، إعداد Nitro وحده لا يفرض رؤوس ردود مضيف الملفات. كما أن `frame-ancestors` لا يعمل داخل meta، وفق [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors).

**التحسين:** مهلة محددة مع إلغاء الطلب وإبقاء النص وإتاحة إعادة المحاولة؛ يمكن استخدام AbortController أو [AbortSignal.timeout](https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal/timeout_static) وفق دعم المتصفحات المستهدف. قبل الربط الفعلي، تأكيد validation وحدود الحجم وrate limiting ومكافحة spam لدى المزود، وقبول CORS للدومين المطلوب، واستخدام HTTPS. ربط endpoint صراحةً ببيئة خطوة generate في GitHub Actions؛ متغيرات runtime لن تغيّر HTML ثابتًا سبق توليده.

**اختبار القبول:** timeout و429 وفشل CORS، والتحقق من وصول رسالة اختبار عبر المزود المعتمد حين يُطلب تفعيله. لم تُرسل أي رسالة إلى مزود خارجي في هذه المراجعة.

## التقييم الأمني وحدود النتائج

- لا توجد حسابات مستخدمين أو قاعدة بيانات أو موارد خاصة متعددة المالكين في الكود المراجع. لم يظهر سطح IDOR أو authorization bypass لتلك الميزات؛ هذا لا يُقيّم خدمة إرسال خارجية مستقبلية.
- لم يظهر استخدام `v-html` أو `innerHTML` أو `eval` لمدخلات الزوار في الأجزاء المفحوصة. Vue يعرض النصوص بالاستيفاء، وJSON-LD يهرب `<` صراحةً. لم يثبت XSS.
- helper الخاص بروابط الموقع يتحقق من HTTP(S) ويمنع الخروج عن origin المحدد، وتغطي الاختبارات بعض صيغ المسارات الخارجية. روابط SEO لا تُبنى من Host المرسل من الزائر.
- لم تظهر مفاتيح سرية في إعدادات public أو نتائج البحث عن الأنماط الشائعة في الكود الحالي. هذا لم يكن مسح أسرار لكل تاريخ Git أو فحصًا لحسابات الاستضافة.
- cookie اللغة ليس جلسة مصادقة؛ لم أعتبر غياب HttpOnly عنه ثغرة دخول. لم يثبت تسريب حالة SSR بين المستخدمين من مراجعة الحالة المحلية للمكونات.
- لم تُختبر بنية DNS/TLS أو إعدادات حساب GitHub أو بريد الشركة، ولم يُنفذ اختبار ضغط أو مسح هجومي على موقع منشور.
- اختبارات المتصفح كانت على Chromium المحلي؛ Safari وFirefox والأجهزة الحقيقية وقارئ الشاشة الفعلي وقياسات Core Web Vitals الميدانية خارج التغطية الحالية.
- ظهر تحذير deprecation أثناء التثبيت لبعض التبعيات غير المباشرة. التحذير ليس CVE مثبتًا؛ نتيجة npm audit بقيت صفرًا.
